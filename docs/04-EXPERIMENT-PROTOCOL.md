# Build 001 experiment protocol

This document is an operational index. The unchanged governing files control if any summary below is incomplete.

## Pre-confirmatory sequence

1. Provision PostgreSQL 18 on demand without a Windows service.
2. Apply the normalized schema and append-only integrity triggers.
3. Initialize the fixture from a deterministic seed and independently verify every provider ref and fixture byte.
4. Pass schema, bitemporal, identity, epistemic, dispatch, recovery, scorer, reset, evidence-capture, and arm-isolation tests.
5. Prove authenticated eyeBROWSE GitHub action and fresh isolated ChatGPT invocation with fixed model/configuration.
6. Generate acquisition episodes. For each source episode, serialize both Memory and Structured forms with recorded source IDs, serializer hashes, byte counts, and estimated tokens.
7. Run exactly 12 pilot trials. Pilot rows remain in `experiments/pilot` and are excluded from all confirmatory input.
8. If and only if a permitted mechanical defect is found before confirmatory exposure, commit a versioned amendment with hashes and evidence. Otherwise record `no amendment`.
9. Commit seed commitments, serializer/scorer hashes, randomization plan encryption/hash, and the pre-confirmatory lock artifact.

## Confirmatory block

For each independent matched block: reset; verify reset blind to the operator; randomize arm order; start one fresh isolated invocation per arm; provide identical common task/tool text and only the arm-specific package; require complete eligible predictions; dispatch one semantic action at a time; preserve provider trace; reobserve through the owning Eye/provider; resolve outcomes in the blinded evaluator; evaluate every proposition; close episodes; and hash raw evidence.

No aggregate comparison is read until every preregistered block is sealed. Multiple actions inside a block are summarized to one block-level primary loss.

## Arm isolation

- Cold receives no acquisition history.
- Memory receives a strong conventional narrative derived from the same selected acquisition episodes as Treatment.
- Treatment receives a deterministic structured package, not evaluator state or future labels.
- Operator credentials cannot read the evaluator database.
- Each arm uses its own worktree/browser target/reset generation and cannot query another arm's kernel/package directory.

## Outcome horizons

H1, H2, and H3 are recorded exactly from the frozen preregistration or a permitted pre-confirmatory amendment. Provider wait is measured separately from active kernel overhead. A receipt is never itself a verified material Outcome; every resolved success requires fresh provider evidence at the required horizon.

## Termination and classification

Hard identity, temporal, prediction-order, evidence-authority, targeting, arm-leak, or fresh-instance failure makes PASS impossible. If a supported fresh-instance mechanism cannot be attested, confirmatory execution is not faked and the only confirmatory classification is `NO VALID CONFIRMATORY CONCLUSION`.
